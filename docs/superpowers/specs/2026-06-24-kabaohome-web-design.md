# 卡宝Home Web MVP 设计方案

日期：2026-06-24
域名：kabaohome.fun
项目：卡宝Home（HarmonyOS NEXT + AGC）

## 1. 背景与目标

卡宝Home 当前是 HarmonyOS NEXT 家庭管理应用，核心能力包括家庭总览、提醒事项（含购物）、家庭备忘、孩子事项、家庭记账、成员与模块管理等。Web MVP 的目标是在 `kabaohome.fun` 上提供一个简洁、温馨、现代的官网与网页版家庭工作台，使用户可以通过浏览器查看和操作 APP 的核心家庭协作数据。

Web MVP 必须满足真实上线要求：登录可信、权限服务端校验、与 APP 数据互通、隐私政策与实际数据流一致、关键流程可验证。

## 2. 产品定位

`kabaohome.fun` 采用“官网 + 登录后家庭工作台”的结构：

- 未登录用户看到产品官网，了解卡宝Home 的理念、功能、隐私安全与数据互通能力。
- 登录用户进入家庭工作台，在浏览器中处理家庭协作事项。
- Web 与 APP 共用同一份云端家庭数据，网页不是独立数据孤岛。

核心主张：**把家的小事，稳稳接住。**

## 3. 首版范围

### 3.1 首版包含

1. 官网首页
2. 手机号验证码登录
3. 家庭总览
4. 提醒事项（含购物清单子视图，与 APP “已合并到提醒中心” 保持一致）
5. 家庭备忘
6. 孩子事项
7. 家庭记账
8. 家庭成员与模块管理
9. 隐私、安全、数据互通说明

> 说明：APP 端 `ModuleManager` 已将 `SHOPPING` 标记为 `isAvailable: false`（合并到提醒中心）。Web 首版不再单独实现购物模块，购物项作为提醒事项的分类/子视图呈现，确保两端数据语义一致。如后续决定在 APP 重新启用独立购物模块，需双方同步变更。

### 3.2 功能边界

#### 官网首页

- 产品主张与 CTA
- 功能亮点：提醒（含购物）、备忘、孩子事项、记账、成员协作
- APP 与网页数据互通说明
- 隐私安全说明
- 登录入口
- 隐私政策与联系信息

#### 手机号验证码登录

- 输入手机号并发送验证码
- 输入验证码完成登录
- 账号与家庭成员身份建立映射
- 失败状态包括验证码错误、发送太频繁、无家庭数据等；未认证阶段不向用户区分“验证码错误”和“手机号未绑定家庭”

**验证码安全硬要求：**

- 单个验证码最多尝试 5 次，超过即失效并需重新发送
- 验证码一次性使用，校验成功后立即作废
- `send-code` 按“手机号 + IP”双维度限流（如单手机号 60s/次、单 IP 10 次/小时）
- `verify-code` 对“手机号未绑定家庭”与“验证码错误”返回相同模糊文案（如“手机号或验证码有误”），防止手机号枚举
- 是否绑定家庭的状态仅在验证码校验通过后才返回，避免未认证状态泄露用户归属

#### 家庭总览

- 今日提醒
- 未完成购物项
- 最近备忘
- 孩子事项摘要
- 本月收支摘要
- 家庭成员与模块快捷入口

#### 提醒事项（含购物子视图）

- 列表和轻量日历视图
- 新增、编辑、完成、删除提醒
- 购物项作为提醒事项的分类/子视图呈现
- 支持新增购物项、完成/取消完成、分类浏览
- 家庭成员准实时同步
- 按 APP 权限显示与操作

#### 家庭备忘

- 查看、搜索、新增、编辑、删除备忘
- 支持共享范围
- 首版使用纯文本或轻格式，不做复杂富文本

#### 孩子事项

- 查看孩子事项列表
- 新增、编辑、完成、删除事项
- 查看成长记录摘要
- 新增简单成长记录
- 按家庭成员与模块共享范围控制可见性

#### 家庭记账

- 查看收支流水
- 新增收入/支出记录
- 分类筛选
- 月度收支汇总
- 预算进度展示（复用 APP 端已有数据结构）
- 按家庭成员与模块共享范围控制可见性

#### 家庭成员与模块管理

- 查看家庭成员
- 邀请/加入说明
- 管理当前成员可见模块
- 不做高风险批量删除，避免误操作

### 3.3 首版不包含

以下模块不进入首版 Web MVP：

- 周期记录
- 健康用药
- 位置共享
- 家庭相册
- 天气穿衣
- 复杂离线编辑

这些模块后续按隐私敏感度、设备能力依赖、权限复杂度逐步开放。

## 4. 视觉与页面设计

### 4.1 视觉方向

采用“暖阳极简”：

- 背景：奶油白、暖米色
- 主色：暖橙、浅粉、柔和珊瑚色
- 辅助色：鼠尾草绿、浅蓝，用于状态区分
- 卡片：大圆角、轻阴影、柔和边框
- 字体：系统中文字体优先，保证清晰稳定
- 动效：轻量淡入、卡片 hover 微抬升，不做复杂动画
- 氛围：像家庭餐桌上的共享面板，而不是企业后台

### 4.2 网站结构

#### 未登录官网首页

1. 顶部导航：Logo、功能、安全、隐私政策、登录入口
2. Hero 区：主标题、副标题、进入家庭 CTA、家庭工作台预览卡片
3. 功能区：家庭总览、提醒（含购物）、备忘、孩子事项、记账
4. 数据互通说明：APP 与网页使用同一家庭数据，修改会同步到家庭成员，权限与 APP 一致
5. 隐私安全区：手机号登录、家庭成员权限、共享范围控制、敏感模块分阶段开放
6. 底部：隐私政策、联系邮箱、ICP 备案号（中国大陆托管为法律强制要求，上线前必须完成备案并在页面底部展示备案号与工信部链接）、版权信息

#### 登录页

- 左侧展示品牌文案或温馨插画
- 右侧提供手机号输入、验证码输入、登录按钮
- 明确说明验证码有效期、频率限制、隐私政策同意
- 错误提示使用用户可理解文案，不暴露技术细节

#### 登录后家庭工作台

桌面端：

- 左侧轻导航
- 顶部展示当前家庭名称、同步状态、成员头像、用户菜单
- 主区域使用大卡片承载当前页面
- 可选右侧“今日家庭动态”栏

移动端：

- 底部 Tab 导航
- 卡片单列展示
- 主要操作按钮固定在底部或右下角

导航包含：

- 总览
- 提醒（购物作为其内 Tab/子视图进入，不单独占顶级导航）
- 备忘
- 孩子事项
- 记账
- 成员与模块

> 移动端底部 Tab 最多展示 5 项时，可将“成员与模块”收入右上角用户菜单，保持底部 Tab 为：总览、提醒、备忘、孩子事项、记账。

### 4.3 功能页统一交互

提醒（含购物子视图）、备忘、孩子事项、记账采用一致模式：

- 顶部标题和新增按钮
- 筛选/搜索
- 列表卡片
- 详情/编辑抽屉或弹窗
- 删除前二次确认
- 空状态有温馨提示和创建按钮
- 权限不足时显示只读状态，并说明原因

## 5. 技术架构

### 5.1 推荐方案

采用独立 Web 项目：

```text
web/
├── src/
│   ├── app/              # 官网、登录、工作台路由
│   ├── components/       # 通用 UI 组件
│   ├── features/         # reminders/memo/kids/accounting
│   ├── lib/
│   │   ├── api/          # 前端 API client
│   │   ├── auth/         # 登录态、手机号验证码
│   │   ├── agc/          # AGC 服务端连接
│   │   └── permissions/  # 权限判断
│   └── types/            # 与 ArkTS 模型对应的 TS 类型
```

首选技术栈：

- Next.js（含 Server API Route / Server Action 作为 Web BFF 层）
- TypeScript
- Tailwind CSS
- AGC Cloud Functions（作为唯一数据写入与权限校验层）
- AGC Cloud DB（仅由 Cloud Functions 访问，Web 不直连）
- 手机号验证码服务（优先评估 AGC 能力，不足时接第三方短信）

**架构边界硬约束：**

- Next.js Server 层负责会话校验、参数清洗、调用 Cloud Function，不直接读写 Cloud DB
- 所有记录级 `visibility` 过滤、`familyId`/`creatorId` 校验由 Cloud Function 强制执行
- Web → Cloud Function 调用需携带服务端凭证（非浏览器凭证），避免前端绕过 BFF 直接调云函数

### 5.2 数据互通

Web 和 APP 共用 AGC 云端家庭数据：

```text
HarmonyOS APP
  ↕ push-data / pull-data
AGC Cloud Functions（统一权限与写入入口）
  ↕
AGC Cloud DB
  ↕
Next.js BFF（会话校验、参数清洗、调用云函数）
  ↕
kabaohome.fun Web
```

Web 不直接信任浏览器传来的 `familyId`、`userId`、`creatorId`、`visibility` 等关键字段，必须由服务端校验或补齐。

### 5.3 统一模型

Web TypeScript 类型镜像 APP ArkTS 模型：

- BaseRecord
- Family
- FamilyMember
- Reminder
- ShoppingItem（Web TypeScript 类型镜像 APP 端 ShoppingItem 模型；UI 上归属“提醒事项”功能模块的购物子视图，但云端仍为独立 Cloud DB 对象类型，不并入 Reminder 记录，确保 APP 按 ShoppingItem 类型查询可同步取到）
- Memo
- KidEvent
- AccountingRecord

所有共享数据必须包含：

```text
id
familyId
creatorId
visibility
visibleMembers
version
createdAt
updatedAt
```

## 6. 权限设计

服务端必须执行三层权限。

### 6.1 登录校验

- 未登录不能访问工作台 API
- 登录态必须来自真实验证码/AGC Auth
- 不允许使用 placeholder、pending 用户作为正式身份

### 6.2 家庭成员校验

- 用户必须属于目标家庭
- 不能通过修改请求中的 `familyId` 访问其他家庭数据
- 写入时服务端以当前用户可访问的家庭上下文为准

### 6.3 记录级可见性校验

- `PRIVATE`：仅创建者可见
- `SELECTED`：创建者和 `visibleMembers` 可见
- `FAMILY`：家庭成员可见

写操作还要校验创建者、管理员、模块授权等规则。Web API 不能只依赖前端隐藏按钮，必须在服务端阻止越权读取和写入。

## 7. API 设计

```text
POST   /api/auth/send-code
POST   /api/auth/verify-code
POST   /api/auth/logout        # 销毁服务端会话并清除 Cookie，HttpOnly Cookie 无法被前端 JS 清除

GET    /api/families/current
GET    /api/dashboard

GET    /api/reminders
POST   /api/reminders
PATCH  /api/reminders/:id
DELETE /api/reminders/:id

GET    /api/shopping-items      # 数据 API，对应 ShoppingItem；UI 入口仍在提醒页购物子视图
POST   /api/shopping-items
PATCH  /api/shopping-items/:id
DELETE /api/shopping-items/:id

GET    /api/memos
POST   /api/memos
PATCH  /api/memos/:id
DELETE /api/memos/:id

GET    /api/kid-events
POST   /api/kid-events
PATCH  /api/kid-events/:id
DELETE /api/kid-events/:id

GET    /api/accounting-records
POST   /api/accounting-records
PATCH  /api/accounting-records/:id
DELETE /api/accounting-records/:id

GET   /api/family-members
PATCH /api/modules
```

所有 API 返回统一响应格式：

```text
success
data
error
metadata
```

HTTP 状态码规范：

| 状态码 | 场景 |
| --- | --- |
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 参数校验失败 |
| 401 | 未登录 / 会话失效 |
| 403 | 无权限（非家庭成员 / 记录不可见 / 非创建者） |
| 404 | 资源不存在 |
| 409 | 版本冲突（返回当前服务端 version，供前端提示刷新） |
| 429 | 限流（验证码、登录、轮询） |
| 500 | 服务端异常 |

错误消息必须面向用户，服务端日志保留详细上下文（堆栈、请求 ID、用户 ID），响应体不包含任何技术细节。

## 8. 同步策略

首版采用在线优先和准实时刷新：

- 页面加载时拉取当前家庭数据
- 写操作成功后立即刷新当前模块
- 提醒（含购物子视图）等高频模块使用短轮询或 SWR 自动刷新
- 冲突处理复用 `version` 字段
- 客户端提交当前版本
- 服务端发现版本落后时返回冲突提示
- 首版提示用户刷新后重试，不做复杂字段级合并 UI

## 9. 安全与隐私硬门槛

真实上线前必须满足：

1. AGC Auth 或手机号验证码登录必须是真实认证链路，不能使用 `pending_` 或 placeholder 用户
2. Cloud Function/API 必须做服务端记录级 `visibility` 过滤
3. 邀请码、验证码、claim token 必须使用安全随机数，不能使用 `Math.random()`
4. 文件/照片存储规则不能允许任意登录用户读取
5. 隐私政策必须与“网页 + 云端同步”实际行为一致
6. 短信发送、登录、邀请码验证必须限流
7. 所有服务端密钥只放环境变量，不进入仓库
8. 会话 Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Strict` 属性；状态变更类 API（POST/PATCH/DELETE）额外采用双重提交 CSRF Token 或同源请求头校验（如 `X-Requested-With`），不依赖 SameSite 单一防护
9. 登录、验证码、邀请码相关 Cookie 设置合理的 `Max-Age` 与 `Path`，登出时立即失效
10. 配置 CSP（含 `frame-ancestors 'none'`）、HSTS、X-Content-Type-Options、X-Frame-Options: DENY、Referrer-Policy、Permissions-Policy；官网 Hero 区的“工作台预览卡片”使用静态截图/模拟数据，不得嵌入真实工作台 iframe
11. API 不返回不可见记录或多余敏感字段
12. 服务端错误不向用户暴露堆栈、密钥、内部路径

## 10. 错误处理

Web 端统一将错误转化为清晰提示：

- 未登录：跳转登录
- 无家庭：引导创建或加入家庭
- 无权限：提示“该内容未共享给你”
- 网络失败：保留当前页面并提示重试
- 版本冲突：提示“数据已被家人更新，请刷新后再编辑”
- 服务端异常：展示温和错误，不暴露技术细节

## 11. 测试策略

### 11.1 单元测试

覆盖：

- 权限判断函数
- `visibility/visibleMembers` 过滤
- 手机号格式校验
- API 参数校验
- 数据模型转换
- 记账金额、分类、月度汇总
- 孩子事项状态流转

### 11.2 API 集成测试

覆盖：

- 未登录访问 API 被拒绝
- 非家庭成员不能访问家庭数据
- 家庭成员只能读取自己可见的数据
- 无权限用户不能编辑/删除他人私有记录
- 版本冲突返回明确错误
- 创建提醒、提醒内购物项、备忘、孩子事项、记账后，APP 可拉取到同一份数据

### 11.3 E2E 测试

关键流程：

1. 打开 `kabaohome.fun`
2. 从官网进入登录
3. 手机号验证码登录
4. 进入家庭总览
5. 新增提醒
6. 在提醒内购物子视图新增购物项并勾选完成
7. 新增备忘
8. 新增孩子事项
9. 新增记账支出
10. 切换到另一个家庭成员，验证权限与可见性
11. 刷新页面后数据仍存在

### 11.4 安全测试

必须验证：

- 不能手改 `familyId` 越权
- 不能手改 `creatorId` 冒充他人
- 不能访问不可见记录
- 短信验证码有限流
- 登录态 Cookie 安全属性、CSRF 防护、登出会话撤销正确
- 验证码一次性使用、最多尝试次数、手机号/IP 双维度限流、模糊错误文案均生效
- API 不返回多余敏感字段
- 服务端错误不泄露密钥或堆栈
- 无硬编码 AGC 密钥

### 11.5 视觉与响应式测试

至少验证这些宽度：

- 320
- 375
- 768
- 1024
- 1440

覆盖页面：

- 官网首页
- 登录页
- 家庭总览
- 提醒列表（含购物子视图）
- 备忘
- 孩子事项
- 记账
- 成员与模块

## 12. 上线部署

建议：

- `kabaohome.fun` 指向 Web 托管平台
- 如部署于中国大陆，ICP 备案必须在公开上线前完成，并在页面底部展示备案号与工信部链接
- Next.js 部署到 Vercel、Cloudflare Pages 或自有 Node 服务之一
- AGC 密钥放部署平台环境变量
- 生产环境强制 HTTPS
- 配置安全响应头
- 部署前跑完构建、测试、E2E、安全检查

## 13. 验收标准

首版完成时必须满足：

1. 官网可公开访问
2. 手机号验证码登录可用
3. 登录后能进入正确家庭
4. 总览能展示真实家庭数据
5. 提醒（含购物子视图）、备忘、孩子事项、记账支持基础 CRUD
6. 网页新增/修改的数据，APP 能同步看到
7. APP 新增/修改的数据，网页刷新后能看到
8. 权限与 APP 一致，不可见内容不会被 API 返回
9. 无权限操作有明确提示
10. 关键流程 E2E 通过
11. 构建通过
12. 无硬编码密钥
13. 隐私政策与实际数据流一致
14. 移动端浏览器可正常使用

## 15. 关键风险

### 15.1 认证未真正打通

如果 APP 或云函数仍使用 placeholder/pending 用户，Web 不能真实上线。必须先建立可信用户身份。

### 15.2 权限只在客户端过滤

Web 会让 API 更容易被直接调用，因此服务端必须做记录级权限过滤。只在 APP 或 Web 前端过滤是不合格的。

### 15.3 数据模型漂移

ArkTS 模型和 Web TypeScript 类型可能随时间不一致。实现时应尽量集中定义类型映射，并在测试中覆盖关键字段。

### 15.4 隐私政策不一致

如果 Web 增加云端同步、手机号登录、提醒内购物、记账和孩子事项处理，隐私政策必须同步更新数据收集、使用、存储和删除说明。
